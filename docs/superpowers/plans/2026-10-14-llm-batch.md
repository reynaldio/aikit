# Batch API (`llm.Batcher`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `llm.Batcher`: submit many chat or embed requests as one provider batch (about half price),
save the ID, check status and read results later. Anthropic, OpenAI, Gemini and Moonshot. Plus metering
(`WithBatchUsage`), a guard wrapper (`guard.WrapBatcher`), a test fake (`llmtest.NewBatcher`), and four parked
follow-ups.

**Architecture:** A new `Batcher` interface next to `Client` and `Embedder`, built by `NewBatcher(cfg)` from
the existing `Config` (no new fields). One `batcher` type in `llm/batch.go` does the rule order, ID format,
limit checks and reply steps, and calls a small internal `batchBackend` per provider. Each backend builds
item bodies with the **same builders the live chat and embed paths use** (small refactors pull them out of
`complete` / `embed`), and parses replies with the live parsers. aikit keeps no state and runs no goroutines.

**Tech Stack:** Go 1.25 (`iter.Seq2`), standard library, the pinned Anthropic SDK (v1.56.0). No new
dependencies.

**Spec:** [docs/superpowers/specs/2026-10-14-llm-batch-design.md](../specs/2026-10-14-llm-batch-design.md).
Read it before your task. Its decisions are final. Where this plan is more exact than the spec, the plan wins.

This is sub-project 4 of 4 (retries → helpers → Embed → **Batch**). Embed is merged but not tagged; Embed and
Batch ship together as v0.11.0 (owner's call when). Do not tag.

### Internal names (package `llm`, shared between tasks)

```go
// batch.go
type batchKind string
const (
    batchChat     batchKind = "chat"
    batchChatJSON batchKind = "chatjson" // every item had a JSONSchema
    batchEmbed    batchKind = "embed"
)

type batchLimits struct {
    maxItems int   // 0 = no cap
    maxBytes int64 // total encoded bytes of all lines; 0 = no cap
}

// batchLine is one item ready to send. body is the provider's own JSON for the
// request part only (the backend wraps it with custom_id / key on submit).
type batchLine struct {
    customID string
    body     []byte
}

type batchBackend interface {
    // supports reports whether this backend can batch kind. batchChatJSON is
    // supported wherever batchChat is.
    supports(kind batchKind) bool
    limits(kind batchKind) batchLimits
    // buildChat encodes one chat item with the live request builder.
    buildChat(model string, maxTokens int, req Request) ([]byte, error)
    // buildEmbed encodes one embed text with the live embed builder.
    buildEmbed(model, text string, kind EmbedKind, dims int) ([]byte, error)
    // submit uploads (if needed) and creates the batch. The create call must use
    // withNoRetry(ctx). Returns the provider's own batch id.
    submit(ctx context.Context, kind batchKind, model string, lines []batchLine) (string, error)
    status(ctx context.Context, providerID string) (BatchStatus, error)
    // results streams the provider's result lines. Called only when status is BatchDone.
    results(ctx context.Context, kind batchKind, model, providerID string) iter.Seq2[rawBatchResult, error]
    cancel(ctx context.Context, providerID string) error
}

// rawBatchResult is one result line as the backend parsed it.
type rawBatchResult struct {
    customID string
    resp     Response  // chat: from the live parser; embed: InputTokens only
    vector   []float32 // embed only, not yet normalized
    err      error     // live parser error (a refusal: resp filled) or the provider's item error
}

// jsonlLines yields each non-empty line of r. No line length cap below 256 MB
// (bufio.Reader, not bufio.Scanner: a long reply is a long line).
func jsonlLines(r io.Reader) iter.Seq2[[]byte, error]

// errCreateMayExist wraps a create-call failure: "the batch may still have been created".
func errCreateMayExist(provider string, err error) error

// retry.go
func withNoRetry(ctx context.Context) context.Context

// llm.go
func checkJSON(resp Response) (Response, error) // checkJSONReply minus the "has a schema" test

// pricing.go
func batchFactor(p Provider) float64 // Anthropic, OpenAI, Google 0.5; Moonshot 0.6; others 1

// anthropic.go
func anthropicParams(model string, maxTokens int, req Request) anthropic.MessageNewParams

func (o *openaiProvider) oaiChatRequest(model string, maxTokens int, req Request) oaiRequest
```

## The core rules (exact; Task 1)

### `BatchID`

- Build: `string(provider) + ":" + string(kind) + ":" + url.QueryEscape(model) + ":" + providerID`.
- Parse: `strings.SplitN(id, ":", 4)`; exactly 4 parts, none empty, kind one of the three, model unescapes →
  else `ErrBadBatchID`. The provider ID is the 4th part as is (it may hold `/` or `:`; Gemini's is
  `batches/abc`).
- `Provider()` / `Model()` return `""` on a malformed ID.

### `NewBatcher`

- Backends: Anthropic when `AnthropicAPIKey != ""`; OpenAI when `OpenAIAPIKey != ""` **and**
  `OpenAIBaseURL == ""`; Google when `GoogleAPIKey != ""`; Moonshot when `MoonshotAPIKey != ""` (base
  `MoonshotBaseURL`, default `https://api.moonshot.ai/v1`). DeepSeek never.
- No backend → `noopBatcher` (`Enabled()` false; Submit/Status/Cancel → `ErrNotConfigured`; `Results`
  yields one `(BatchResult{}, ErrNotConfigured)`).
- Keeps `Profiles`, `EmbedModel`, `MaxTokens` (≤ 0 → 1024, as in `New`), `RequestTimeout`, the set of
  configured chat providers (for "custom OpenAIBaseURL" and DeepSeek detection), and the logger.
- `Enabled()` true when at least one backend exists.

### `SubmitChat` rule order

1. Model: `b.Model` if non-nil and not empty. Else `Task`: `prof := defaultTaskProfile[b.Task]` (missing or
   empty Task → `ProfileChat`), `ref := cfg.Profiles[prof]`. Else (ref empty) the first non-empty of
   Profiles fast, chat, deep, vision, document, transcribe, search. Still empty → `ErrNotConfigured`.
   No `usable()` swap: a profile on a provider with no batch backend is caught in step 2–3, not replaced.
2. `ErrBatchUnsupported` (wrap with the provider name) when: provider is DeepSeek; provider is OpenAI and
   `OpenAIBaseURL != ""`; provider is unknown.
3. No backend for the provider → `ErrNotConfigured`.
4. Item checks, in item order; the first failure returns an error naming the index (`"llm: batch item %d:
   ..."`). Nothing is sent.
   - `len(Items) == 0` → error.
   - `CustomID` matches `^[A-Za-z0-9_-]{1,64}$`; not seen before in this batch.
   - `Request.Model` nil, empty, or equal to the batch ref.
   - `Request.Task` empty or equal to `b.Task`.
   - `Request.OnEvent == nil`.
   - Schema: item 0 decides (`len(JSONSchema) > 0` → `batchChatJSON`, else `batchChat`); any later item
     that differs → error "mixes items with and without JSONSchema".
5. Build: `maxTokens = Request.MaxTokens`, else the config default. `backend.buildChat(...)`. An error →
   wrapped with the index.
6. Limits: `len(lines) > maxItems` (when > 0) or sum of `len(body)` > `maxBytes` (when > 0) →
   `ErrBatchTooLarge` with the numbers.
7. `providerID, err := backend.submit(ctx, kind, model, lines)`. Error → returned as is (the backend already
   wrapped a create failure with `errCreateMayExist`).
8. Return the built `BatchID`.

`SubmitEmbed` is the same shape: model from `b.Model` else `Config.EmbedModel` (empty → `ErrNotConfigured`);
Google model loses a `models/` prefix; `ErrBatchUnsupported` for Anthropic, Moonshot, DeepSeek, OpenAI with
`OpenAIBaseURL`; `ErrNotConfigured` for no backend; checks: items non-empty, CustomID rule and uniqueness,
`Text != ""`, `Dimensions >= 0`, `Kind` in `""`/`EmbedQuery`/`EmbedDocument`; build with `buildEmbed`;
limits; submit with `batchEmbed`.

### `Status` and `Cancel`

Parse the ID (`ErrBadBatchID`), find the backend (`ErrNotConfigured` when missing), apply the default
deadline (ctx without one → `RequestTimeout`, or 60s when 0), call the backend.

### `Results` reply steps

1. Parse the ID; no backend → yield one error and stop.
2. `st, err := Status(ctx, id)`. Error → yield it. `BatchFailed` → yield `fmt.Errorf("llm: batch failed:
   %w", st.Err)`. `BatchRunning` → yield `ErrBatchNotDone`.
3. Range over `backend.results(ctx, kind, model, providerID)` (ctx only, no extra deadline). For each raw:
   - Set `resp.Provider` and `resp.Model` from the ID.
   - Chat, `raw.err == nil`, kind `batchChatJSON` → `resp, err = checkJSON(resp)`.
   - Embed, `raw.err == nil`: empty vector → `Err` "empty vector"; else copy and `normalizeVec`.
   - Yield `BatchResult{CustomID, Response, Vector, Err}`. `yield` false → return (the backend's iterator
     closes its body when its own yield returns false).
4. A backend iterator error → yield `(BatchResult{}, err)` and stop.

### `Wait`

Loop: `st, err := b.Status(ctx, id)`; error → return `(st, err)`; state Done or Failed → return `(st, nil)`;
then wait `every` (≤ 0 → 30s) with a timer and `select` on `ctx.Done()` → return `(st, ctx.Err())`.

### `CollectResults`

Append each result; on the first non-nil iterator error return the slice so far and the error.

## Money rule: never create a batch twice (exact; Tasks 1–5)

1. `withNoRetry(ctx)` puts a private key on the context. In `retryTransport.RoundTrip`, read it once at the
   start: when set, do exactly one `t.base.RoundTrip(r)` and return its result untouched (no status check,
   no drain, no sleep). Requests without the key behave exactly as today.
2. Every backend's create call uses `withNoRetry(ctx)`:
   - Anthropic `client.Messages.Batches.New(withNoRetry(ctx), ...)`. The SDK's own retries are already 0
     (`option.WithMaxRetries(0)`), and the SDK passes ctx to our transport.
   - OpenAI/Moonshot `POST {base}/batches`.
   - Gemini `POST /models/{m}:batchGenerateContent` and `:asyncBatchEmbedContent`.
3. Any error from the create call (transport error, non-2xx, unreadable body, missing id in the reply) is
   returned as `errCreateMayExist(provider, err)`: message `"<provider>: create batch failed; the batch may
   still have been created, check the provider console before resubmitting: <err>"`, and it wraps `err`.
4. Uploads, status, results and cancel never use `withNoRetry`.
5. Tests (Task 1 for the transport; each backend task for its create call): a 503 on create → exactly one
   request reached the server and the error text contains "may still have been created"; a 503 then 200 on
   upload and on status → retried and succeeds.
